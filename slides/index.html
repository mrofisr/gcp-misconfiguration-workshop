Total: 90 minutes · Seven segments · No cloud knowledge assumed

The agenda is the contract for the session. Keep the pace: ten minutes for setup, ten for the plain-language intro, fifteen to find the problems, twenty for fix one, fifteen for fix two, ten to verify, and ten for recap and teardown. Everything is already prepared for participants.

1 · Setup 10 min

Install and sign in to Antigravity CLI; run doctor

Show the three platform command forms. Participants run doctor. Expected: tool checks pass; cloud checks pass in the prepared project. If a check fails, use the facilitator guide troubleshooting table.

Three command forms, one result

make doctor        # macOS / Linux
task doctor        # any platform with go-task
.\Setup.ps1 doctor # Windows PowerShell

Expected: tool checks pass and cloud checks pass in the prepared project.

If a check fails → facilitator guide troubleshooting table.

All four commands are available to everyone. doctor is read-only. The first Windows run of Setup.ps1 also installs prerequisites; that is why setup owns the first ten minutes.

2 · Plain-language intro 10 min

A bucket is a folder in the cloud; IAM is who may open it

Use the words from glossary.md only after defining them. Say explicitly: "You do not need to know how to set any of this up."

Three sentences

  1. Cloud = someone else's computer.
  2. Bucket = a folder there.
  3. IAM = the guest list.

You do not need to know how to set any of this up.

Define each term before using it again. Do not introduce IAM theory, roles, or policy syntax here; the guest-list image is enough for this audience.

See it: bucket and guest list

Who is on the guest list decides who can open the bucket.

Operate the control to show an allowed visitor and a blocked visitor. The readout follows the same state as the figure, so the visible change and the label agree.

3 · Find the problems 15 min

Ask Gemini 4 to review the starter repo in plain language

Open starter/ in Antigravity CLI. Prompt 1 comes from the participant guide: ask Gemini 4 to review Terraform and Go code and explain risks simply.

Prompt 1 — review, do not fix yet

Open starter/ in Antigravity CLI and ask Gemini 4 to review the Terraform and Go code and explain the risks in plain language.

Optional 60-second Security Command Center screenshot — the lab does not depend on it.

Keep the lab independent of Security Command Center tiers and detectors. The screenshot is a demo only; nobody's progress depends on seeing it.

4 · Fix 1 — bucket and permissions 20 min

Make the bucket private and reduce the permission

Prompt 2 asks Gemini 4 for the smallest Terraform edit. Edit terraform/main.tf, run plan, then apply. Checkpoint: the bucket is no longer public.

Smallest Terraform edit

Ask Gemini 4 for the smallest edit that makes the bucket private and reduces the permission.

make plan   # inspect before changing
make apply  # create / update the lab resources

Use task or .\Setup.ps1 on other platforms.

plan is read-only. apply changes GCP resources and is available to everyone; state that before running it. Keep the edit to Terraform source only.

See it: public bucket and permission

Before: public bucket and a wide permission. After: private bucket, narrower permission.

Move the control from before to after. Point out that the guest list shrinks at the same time the bucket stops being public; both changes are part of fix one.

Checkpoint

The bucket is no longer public.

Confirm the checkpoint before moving on. If it has not changed, go back to plan and the Terraform edit rather than starting fix two.

5 · Fix 2 — app credential and input 15 min

Remove the hardcoded key and validate the file name

Prompt 3 asks Gemini 4 about the hardcoded key and unsanitized file name. Edit app/main.go, redeploy, smoke test. Checkpoint: no hardcoded key; unsafe name rejected.

Ask about the app

Ask Gemini 4 why a key in source is unsafe and how a file name could escape the bucket folder.

Edit app/main.go, redeploy, then smoke test.

Keep the app fix to Go source: replace the hardcoded credential and validate the object name. No new billable resource is needed.

See it: key in code and unsafe name

Before: a key under the mat and an unchecked name. After: a checked request and no key in code.

Move the control from before to after and read the change aloud: the credential is no longer in source, and a name that tries to escape is rejected.

Checkpoint

No hardcoded key; unsafe name rejected.

Both parts of the checkpoint must hold before the group moves to verification.

6 · Verify 10 min

Use gcloud and the app to prove both fixes worked

Run the gcloud verification commands from the participant guide. Record before/after evidence in the tables.

Evidence, not assumptions

Inspect the bucket, IAM policy, and Cloud Run service with gcloud CLI or MCP.

Smoke test the app and record before/after evidence in the guide's tables.

gcloud CLI works as a fallback if MCP/ADC is unavailable. Each fix needs a recorded observation, not just a claim that the edit was applied.

7 · Recap and teardown 10 min

What changed, why, and run destroy

Recap: two fixes, one idea — least access and no secrets in code. Run destroy. Confirm with doctor that nothing remains.

Two fixes, one idea

  • Least access: the bucket is private and the permission is narrower.
  • No secrets in code: the credential is removed and the file name is checked.
make destroy   # or: task destroy / .\Setup.ps1 destroy
make doctor    # confirm nothing remains
destroy removes the lab resources and is available to everyone. Finish with doctor so the room can see a clean environment; remind participants that Gemini 4 needs a separate subscription.
